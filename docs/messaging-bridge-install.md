# Messaging Bridge Installation Guide

This document explains how to install and verify the **CRM Sidekick messaging bridge** on Windows. In this repository, the messaging bridge is implemented as a **Chrome/Edge Native Messaging Host** named `com.ttmt.crm_sidekick.zip_bridge`. The browser extension uses it to:

- confirm the bridge is reachable with a `ping` request,
- open a native Windows folder picker when the user chooses a save folder, and
- silently create zip files in the selected destination folder instead of relying on the browser download flow.

## What gets installed

The Windows bridge is packaged for end users as two executable files:

1. `zip_bridge_host.exe` — the native host process that receives messages from the extension and runs the Windows-side work.
2. `native_host_installer.exe` — the installer that copies the host executable into the user's local app-data folder, generates the Native Messaging manifest, and registers that manifest for both Chrome and Edge.

The source files that produce those executables remain in this repo as:

- `zip_bridge_host.py`
- `native_host_installer.py`
- `build_native_host.ps1`

When the installer runs successfully, it:

- copies `zip_bridge_host.exe` into `%LOCALAPPDATA%\TTMT\CRM Sidekick Native Host`,
- writes a manifest file named `com.ttmt.crm_sidekick.zip_bridge.json` in that same folder,
- creates the current-user Chrome registry key for the host, and
- creates the current-user Edge registry key for the host.

## Prerequisites for end users

Before installation, make sure the target workstation has all of the following:

### 1. Windows
The installer exits unless it is run on Windows.

### 2. Google Chrome or Microsoft Edge
The installer writes Native Messaging registration entries for **both** browsers under the current user's registry hive. The extension can then connect from whichever of those browsers you are using.

### 3. PowerShell available
The packaged native host uses PowerShell for two actions:

- showing the Windows folder picker dialog,
- creating zip files with `Compress-Archive`.

### 4. The CRM Sidekick extension ID
The manifest generated by the installer only allows origins that match the extension ID stored in the `CRM_SIDEKICK_EXTENSION_ID` environment variable at install time.

If you do **not** set that variable first, the installer still runs, but the manifest will contain the placeholder value `REPLACE_WITH_EXTENSION_ID`, which will prevent the real extension from connecting.

## Build the packaged executables

This step is only for the person preparing the Windows installer package.

1. Open **PowerShell** in the repository root.
2. Run:

```powershell
.\build_native_host.ps1
```

That script installs `PyInstaller` if needed, then produces:

- `dist\zip_bridge_host.exe`
- `dist\native_host_installer.exe`
- convenience copies at the repo root:
  - `zip_bridge_host.exe`
  - `native_host_installer.exe`

Distribute `native_host_installer.exe` together with `zip_bridge_host.exe`.

## Step 1: Get the extension ID

You need the exact extension ID for the build you plan to use.

### If you are loading the extension unpacked
1. Open Chrome or Edge.
2. Go to the browser's extensions page:
   - Chrome: `chrome://extensions`
   - Edge: `edge://extensions`
3. Turn on **Developer mode**.
4. Load the extension from this repository if it is not already loaded.
5. Copy the extension's ID.

### If you are using a packaged/published extension
Copy the installed extension's ID from the extensions page.

## Step 2: Put the packaged files together

Place these two files in the same folder on the Windows machine:

- `native_host_installer.exe`
- `zip_bridge_host.exe`

The installer looks for `zip_bridge_host.exe` next to itself, and also supports finding it in a local `dist` folder when run from the repository.

## Step 3: Set the extension ID environment variable

Open **PowerShell** in the folder that contains the executables and set the variable the installer expects:

```powershell
$env:CRM_SIDEKICK_EXTENSION_ID = "YOUR_EXTENSION_ID"
```

Replace `YOUR_EXTENSION_ID` with the exact browser extension ID.

### Optional: verify the value before installing

```powershell
$env:CRM_SIDEKICK_EXTENSION_ID
```

## Step 4: Run the installer

Run the packaged installer:

```powershell
.\native_host_installer.exe
```

### What a successful install does

The installer will:

1. locate `zip_bridge_host.exe`,
2. create `%LOCALAPPDATA%\TTMT\CRM Sidekick Native Host` if needed,
3. copy the host executable into that folder,
4. build a manifest with the allowed origin `chrome-extension://YOUR_EXTENSION_ID/`,
5. save the manifest to `%LOCALAPPDATA%\TTMT\CRM Sidekick Native Host\com.ttmt.crm_sidekick.zip_bridge.json`,
6. register the manifest path in:
   - `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.ttmt.crm_sidekick.zip_bridge`
   - `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.ttmt.crm_sidekick.zip_bridge`

### Expected installer output

A successful install prints messages similar to:

```text
Installed TTMT CRM Sidekick native host.
Host executable: C:\Users\<you>\AppData\Local\TTMT\CRM Sidekick Native Host\zip_bridge_host.exe
Manifest: C:\Users\<you>\AppData\Local\TTMT\CRM Sidekick Native Host\com.ttmt.crm_sidekick.zip_bridge.json
```

## Step 5: Verify the installed files

Check that the install folder exists:

```powershell
Test-Path "$env:LOCALAPPDATA\TTMT\CRM Sidekick Native Host"
```

Check that the copied host exists:

```powershell
Test-Path "$env:LOCALAPPDATA\TTMT\CRM Sidekick Native Host\zip_bridge_host.exe"
```

Check that the manifest exists:

```powershell
Test-Path "$env:LOCALAPPDATA\TTMT\CRM Sidekick Native Host\com.ttmt.crm_sidekick.zip_bridge.json"
```

Open the manifest to verify the extension ID and host path:

```powershell
Get-Content "$env:LOCALAPPDATA\TTMT\CRM Sidekick Native Host\com.ttmt.crm_sidekick.zip_bridge.json"
```

Confirm that:

- `name` is `com.ttmt.crm_sidekick.zip_bridge`,
- `type` is `stdio`,
- `path` points to the installed `zip_bridge_host.exe`, and
- `allowed_origins` contains your real extension ID.

## Step 6: Verify the registry entries

Check the Chrome registration:

```powershell
Get-ItemProperty "HKCU:\Software\Google\Chrome\NativeMessagingHosts\com.ttmt.crm_sidekick.zip_bridge"
```

Check the Edge registration:

```powershell
Get-ItemProperty "HKCU:\Software\Microsoft\Edge\NativeMessagingHosts\com.ttmt.crm_sidekick.zip_bridge"
```

Each default value should point to the manifest file you verified in the previous step.

## Step 7: Reload the browser extension

After installation:

1. go back to the browser extensions page,
2. reload the CRM Sidekick extension, and
3. reopen the Sidekick panel.

This ensures the extension sees the newly registered native host.

## Step 8: Verify the bridge inside the UI

The panel includes a **Zip save folder** setting that depends on the native bridge.

### Expected behavior after a successful install

1. Open the Sidekick panel.
2. Go to the settings section.
3. Find **Native Windows zip save folder**.
4. Click **Choose native zip folder**.
5. A native Windows folder browser dialog should appear.
6. Select a folder.
7. The status line should update to show the selected folder name.

### If the bridge is not available
The extension will show an alert similar to:

- `Native zip bridge unavailable: ...`

and the status line remains in the disconnected state.

## How the bridge works after installation

Once installed and connected:

1. the extension sends a `ping` message to confirm the host is reachable,
2. the extension can send `pick_folder` to open the Windows folder picker,
3. when trial vocab or Grid files need to be saved, the extension sends `zip_files` with:
   - the destination folder,
   - the intended zip filename,
   - the selected files encoded as base64,
4. the native host writes those files to a temporary directory,
5. the native host runs PowerShell `Compress-Archive`, and
6. the finished zip is written directly to the chosen folder.

## Troubleshooting

### Problem: The installer says the packaged host executable is missing
Make sure `zip_bridge_host.exe` is in the same folder as `native_host_installer.exe`, or rerun `build_native_host.ps1` from the repository so the installer can also find `dist\zip_bridge_host.exe`.

### Problem: The extension says the native bridge is unavailable
Check the following in order:

1. **Wrong extension ID in the manifest**  
   Open the manifest and confirm `allowed_origins` includes the exact installed extension ID.

2. **Installer was run without setting `CRM_SIDEKICK_EXTENSION_ID`**  
   If the manifest contains `REPLACE_WITH_EXTENSION_ID`, set the variable correctly and rerun the installer.

3. **Browser was not reloaded after installation**  
   Reload the extension after the installer finishes.

4. **Manifest path points to the wrong file**  
   Confirm the manifest `path` ends in `zip_bridge_host.exe` and that the file exists.

5. **Registry values were written under a different Windows account**  
   The installer writes to `HKCU`, so it must be run by the same user who runs the browser.
